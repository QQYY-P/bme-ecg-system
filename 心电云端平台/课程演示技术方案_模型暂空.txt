当前腾讯云数据链路与现有CardioEdgeAI v1 INT8模型均已部署并验证；当前状态、验证范围、启动步骤、
模型开关与回退说明以同目录README.txt为准，已替代本文中的阶段性部署安排。
下文“模型未接入”“后续事项”等表述仅说明当时计划；电脑本地默认仍可保持模型空置。
适用范围：课程作业与短期演示；不建设长期运行平台。

一、这次具体完成什么

实现一条可验证的数据闭环：
AD8232/STM32 → 树莓派采集和本地保存 → HTTP上传 → 云端保存 → Web查看。
云端返回接收确认，树莓派显示上传成功、待上传或失败。

首期交付四项功能：
1. 上传：上传已保存的原始心电数据及来源、采样率、质量标记等信息。
2. 存储：云端保存完整已接收数据，支持按会话查询和下载。
3. 展示：网页显示波形、设备、会话、接收时间、点数和上传状态。
4. 返回：云端返回实际入库的数据块编号、点数和校验值。

模型按用户要求暂空：不加载权重，不运行分类、大模型分析或重训。
页面固定显示“模型未接入”，model_status 为 not_configured，model_result 为 null。
接收确认仅表示数据已经保存，不能写成“模型复核通过”。
课程原要求中的模型复核、模型重算和边缘实时推理，需在报告中标为后续事项。

二、当前项目可以直接复用的部分

树莓派心电终端已有：360 Hz采集、本地波形、心率/RR、信号质量检查、完整记录和CSV导出。
当前 app.py/controller.py 入口没有启用分类模型，本方案保持这一状态。

recording.py 已保存：
- session.json：会话元数据。
- index.sqlite：已提交的数据块索引和事件。
- chunks/*.bin：原始ADC及采样编号、段编号、序号、质量标记、模式。
- chunks/*.json：数据块描述和SHA-256校验值。
- quality.json：会话质量摘要。

上传器只读取已提交到索引的数据块，不从界面的短时显示缓存取数据。
先完成“采样数据、会话和质量摘要”上传；心率/RR若要显示，须额外接入带时间戳的指标快照。
现有云端目录仅见虚拟环境，不将其视为已有云端服务。

三、最小技术组合

树莓派：一个独立Python上传脚本，和现有采集程序分开运行。
通信：HTTP接口；每约5秒检查一次新数据块，停止采集后继续补传剩余块。
后端：FastAPI + Uvicorn，一个服务进程。
数据库：SQLite，保存会话、数据块索引、接收状态及可选指标。
原始数据：保存到服务器本地数据目录，继续保留已有二进制块及校验值。
网页：后端提供一个简单HTML页面，显示波形、记录列表及状态，无需独立前端工程。
部署：一台普通CPU云主机；优先使用已有、学校提供或短期租用的资源。

此规模先采用普通Python环境启动，Docker作为可选打包方式。
不设置MQTT代理、Kubernetes、Redis、独立API网关或专用GPU服务器。
主机容量在短时联调后按实际内存和存储量确定，不预先承诺某一配置的性能。

四、上传与保存规则

1. 每次发现已提交的新块，发送原始二进制文件及其描述信息。
   会话信息包括 device_id、session_id、source、sample_rate_hz、vref_v。
   数据块保留 chunk_id、sha256、sample_count 和逐点 mode、flags、segment_id。
   本地文件路径和串口设备路径不需要上传。

2. 用 device_id + session_id + chunk_id 唯一定位一个块。
   重复上传相同内容直接返回原接收确认；同编号而校验值不同则返回冲突，不覆盖旧数据。

3. 云端检查数据长度、版本、采样率和SHA-256，文件写完且索引提交后才确认成功。
   临时文件不展示；启动时检查未完成写入，避免把半个文件当作完整记录。

4. 树莓派收到匹配的接收确认后，将上传进度写入独立的小型状态文件。
   网络超时后保留本地数据，下次继续；重启后从已确认进度恢复。
   使用原子替换保存进度；若确认已到达但进度未保存，重复发送仍能安全去重。
   上传失败不能阻塞串口采集、本地记录或屏幕刷新。

5. 会话结束时上传最终点数、块清单和质量摘要。
   云端核对完整后才显示“上传完成”；缺块显示“待补传”，不能仅凭停止按钮判定完成。
   上传成功后保留树莓派原始记录，便于课程核对与导出。

6. 来源必须保留：人体实采、板端模拟、本地合成、文件回放分别显示。
   mode=1单独不能区分板端模拟和本地合成，应结合source解释。
   时间轴按已有采样编号和连续段解释，不能将收包时间称为精确硬件采样时刻。

五、页面只保留课程演示所需内容

- 顶部：设备名、会话、来源、最近接收时间、已接收点数。
- 中间：最近10秒心电波形，可切换历史会话。
- 下方：采样率、质量状态、上传进度、完整CSV下载。
- 模型区域：显示“未接入模型”，不生成分类概率、诊断或模拟复核结论。
- 可选：显示树莓派上传的心率/RR；没有有效指标或数据已过期时显示“--”。

网页约每2秒查询一次数据即可，不追求逐点网络刷新。
波形使用ADC值或ADC换算电压V；不直接标成皮肤心电mV。
无效点和采集中断显示为缺口，不连线掩盖；旧数据注明时间，不冒充正在采集。

六、建议接口（实施时再固定请求结构）

GET  /health                         服务健康检查
PUT  /api/sessions/{session_id}        创建或更新会话信息
PUT  /api/sessions/{session_id}/chunks/{chunk_id}
                                      上传数据块，返回保存确认
POST /api/sessions/{session_id}/complete
                                      提交最终清单并核对完整性
GET  /api/sessions                    查询记录列表
GET  /api/sessions/{session_id}/waveform
                                      获取指定范围波形，限制单次返回点数
GET  /api/sessions/{session_id}/export 下载完整CSV
GET  /api/sessions/{session_id}/analysis
                                      返回not_configured和null

首版可以限定一个设备，设备身份由配置和访问凭证确定，不能任由请求冒用。
模型入口只留占位，不创建后台推理任务或虚假的处理进度。

七、短期部署与演示方式

步骤1：先在电脑启动服务，验证树莓派上传、保存和网页查看。
步骤2：将同一份服务复制到云主机，安装依赖并启动，数据目录单独保存。
步骤3：树莓派上传到实际云主机，电脑浏览实际云主机上的页面并下载数据。

默认演示可采用SSH端口转发：云端服务只监听127.0.0.1，树莓派和演示电脑分别建立隧道。
HTTP请求通过SSH加密连接到云主机，无需为此次演示另配公开网站域名。
该方式需要云主机SSH允许端口转发；访问页面的电脑必须保持隧道连接。
服务与数据确实在云主机上，因此属于云端部署；仅把电脑服务暴露到公网则不能这样表述。
若需要让老师或手机直接通过公共链接访问，再增加HTTPS入口和简单访问认证。
OpenSSH的本地端口转发机制见官方资料[2]。

演示结束后：导出代码、依赖清单、CSV、日志及截图；核对本地备份可打开。
随后按实际服务商规则释放不再使用的主机和附属收费资源；仅关机不等于全部停止计费。
本文件不涉及购买、启动或删除任何云资源。

八、课程Demo与验证

建议演示顺序：
1. 开始采集，树莓派本地波形正常。
2. 网页出现同一个会话，点数增加、波形更新。
3. 暂停网络约20秒，树莓派继续采集和保存，网页显示数据已过期。
4. 恢复连接，待上传块补齐；重复发送一个块，云端点数不重复增加。
5. 停止采集并等待传完，下载CSV，核对两端点数、来源和数据块校验值。
6. 展示模型区域“未接入模型”，说明后续扩展位置。

以上时长属于建议测试设计，并非教师给定的额外验收标准。
可以先用合成数据验证软件闭环；报告和截图必须标清来源。
若要证明真实采集上传，需要单独保留真实硬件会话证据。
仅在电脑上完成步骤1，报告只能写“本地联调完成”；实际迁移云主机后才能写“云端已部署”。
