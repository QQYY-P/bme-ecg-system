树莓派心电终端代码设计 V1.0：本地屏幕版
日期：2026-10-26
状态：代码设计稿。本文中的新增模块、界面和验收项目尚未实现或验收。

一、首要目标与硬件分工

心电模块 AD8232 → STM32 → USB-TTL → 树莓派 2 → 外接显示器。

1. 心电模块输出模拟信号；STM32 完成 ADC 定时采样及串口发送。
2. 沿用现有 STM32 工程：360 Hz、12 位 ADC、115200 / 8N1、无流控。
3. 树莓派负责接收、波形处理、屏幕绘图、记录和现有三分类模型推理。
4. 主界面运行在树莓派所连接的屏幕上。笔记本通过 VS Code / SSH 开发、部署和检查日志。
5. 本设计先采用现有外接显示器和键鼠，按 HDMI 显示路径考虑；实际分辨率和是否触摸待确认。
6. 首版优先做到“屏幕显示真实心电 + 完整保存”。模型、网络任务应与这条路径隔离。

已确认的开发基础：
- Raspberry Pi 2 Model B Rev 1.1，armv7l，Python 3.13.5；SSH / VS Code 连接已经验证。
- 2026-10-26 的设备检查未发现 /dev/ttyUSB*、/dev/ttyACM* 或 USB 转串口设备。
- 图形会话、Tk 窗口和中文字体仍需在树莓派实际屏幕上验证。
- OS Lite 本身没有桌面。若继续使用 Lite，部署阶段补充轻量 X11 会话、窗口管理器及 Tk 支持；不能只在文本控制台启动 Tkinter 界面。
- Python 版本已符合现有方案的 3.11+ 目标；NumPy/SciPy 等依赖的实际版本与可用性另行记录。

二、首版主屏设计

最小布局基准为 800×480，窗口可随实际显示分辨率缩放，支持全屏和 Esc 退出全屏。

│ 心电采集终端   实采/模拟/回放   串口状态   信号状态   录制时间 │
├───────────────────────────────────────────────┬─────────────┤
│                                               │ 心率  --    │
│             滚动心电波形                      │ RR    --    │
│       默认最近 10 秒，带时间轴和纵轴           │ 模型预测    │
│                                               │ 等待数据    │
├───────────────────────────────────────────────┴─────────────┤

└─────────────────────────────────────────────────────────────┘

显示约定：
- 数据源始终可见：“STM32 实采”“合成模拟”或“文件回放”，三者不能混淆。
- 默认单条处理后波形，可切换原始或双波形对照；首版主要优化单波形。
- 波形窗默认 10 秒，可选 5 秒；刷新初值为 10 帧/秒，可板测后提高到 15 帧/秒。
- 显示刷新率与采样率分开：采样和保存仍保持完整 360 Hz 数据。
- 使用 Tkinter Canvas 更新已有折线；只对显示进行按像素分桶的最小/最大值抽稀，保留尖峰及先后顺序。
- 断点、导联无效、饱和和失步处断开曲线；不同连续段之间不能画连接线。
- 纵轴原始模式显示“ADC 输入电压 V”，由 ADC×Vref/4095 换算。
  Vref 默认 3.300 V，并标为未校准；不直接把它写成皮肤心电幅度 mV。
- 处理后模式注明去基线等处理；滤波输出可超出原 ADC 电压范围，显示不应静默截断。
- 心率、RR 和状态每秒刷新；缺少有效数据时显示“--”，不把旧心率显示成当前值。
- 模型预测附结果时间和延迟，显示 N/PVC/PAC 及概率；尚未计算时显示等待原因。
- “暂停显示”只冻结画面。串口接收、存储和后台分析继续运行；恢复时显示最新数据。
- 首版“停止采集”关闭本次采集并完成落盘；重新连接建立新的会话。
- HRV、详细概率、记录导出、网络状态放在独立页面，避免挤占主波形。

四、运行结构与线程/进程

串口线程
  → protocol：解析帧、发现边界
  → 原始记录队列 → 存储线程 → 原始块 + SQLite
  → 分析队列 → 分析线程 → 显示缓存、心率和质量快照
  → 模型队列 → 独立模型进程 → 分类结果与耗时

Tkinter 主线程
  → 定时读取快照和事件 → 刷新树莓派屏幕
  → 发送连接/停止/暂停显示等控制请求

未来上传线程
  → 只读取已提交的数据块 → 板外服务器

职责边界：
- Tkinter 控件只能由主线程操作；回调不执行串口等待、推理、数据库导出或网络请求。
- 串口只由接收线程持有。接收线程只做有限解析、质量标记和队列投递。
- 存储线程是 SQLite 的唯一写入者，界面查询使用独立只读连接。
- 模型进程显式使用 spawn；程序入口带 main 保护，三个模型每次启动只加载一次。
- BLAS 线程数在模型进程导入 NumPy 前设置；先比较 1/2 线程，不预先宣称某配置更快。
- 各队列必须有界。下面是初始设计值，均须实际压测后确认：
  原始记录队列：64 个至多 36 点的数据块，常速约 6.4 秒缓冲。
  分析队列：32 个至多 36 点的数据块，常速约 3.2 秒缓冲。
  模型队列：8 个至多 360 点的数据块；连续正常输入按约 1 秒聚合时约 8 秒待处理数据。
  状态快照：只保留最新值；事件另走有界队列，不无限堆积。
- 模型投递适配器在同一连续段内把串口小块聚合到 360 点后入队；遇段边界或正常停止立即拆块。
  不跨段补满，也不直接以 36 点块入队后仍声称有 8 秒缓冲；实际积压按样本数和接收时间计算。
- 记录队列满：立即停止本次接收，标记“保存不完整”，尽力完成已入队数据的落盘。
  原始数据不可通过丢弃旧块来维持表面流畅。
- 分析队列满：保存原始数据，记录未分析范围，递增 analysis_generation，界面显示分析落后。
  后续块携带新分析代号。分析线程检查段编号及预期起点，代号变化或缺块时先 reset。
  旧代号的迟到快照不得重新显示为当前心率；当前值保持“--”直到新段重新有效。
- 模型队列满：保存原始数据，记录未分类范围，切换模型代号并重新积累上下文。
- 模型进程崩溃：提示模型不可用，原始接收、保存和基本显示继续工作。
- 使用明确的计数/回执跟踪待处理量，不以 multiprocessing.Queue.qsize()/empty() 作为正确性依据。

五、数据契约与时间含义

SampleBlock（只读，发布后不可修改）
- session_id：本次连接会话的 UUID。
- segment_id：物理数据连续段编号；断点后增加。
- first_sample_id：本会话收到的完整帧累计编号，始终递增。
- segment_sample_start：本段内采样位置，从 0 起算。
- sequence：STM32 原始 uint8 序号数组。
- raw_adc：原始 uint16 数组，保留 0xFFFF。
- quality_flags：逐点标记导联无效、饱和、段边界等。
- received_utc、received_monotonic：块的接收时间；不是硬件精确采样时间。
- sample_rate_hz=360、source_kind、schema_version。

AnalysisBlock
- SampleBlock 加 analysis_generation（分析处理代号），用于隔离分析队列丢块后的旧结果。
- AnalysisSnapshot 回传同一代号；主线程只接受当前代号的即时指标。

ModelBlock
- SampleBlock 的会话/连续段/索引，加 generation（模型处理代号）。
- 同一代号中的起点必须等于上个块的终点；不满足时立即 reset。

BeatResult
- session_id、segment_id、generation、peak_sample_index。
- label、probabilities、model_id、模型/预处理版本。
- sample_time_s（段内）、produced_utc、queue_wait_ms、compute_ms。
- algorithm_confirmation_delay_ms、tail、source_kind。
- “结果总延迟”必须说明起算方式，不能把现有 latency_s 当成包含计算/排队的总延迟。

时间规则：
- 连续段内用 sample_index/360 表达采样相对时间。
- 接收 UTC 用于记录关联；单调时钟用于超时和耗时。
- 8 位序号只能观察部分异常，不能恢复全部丢失样本或精确跨缺口时间。
- sample_id、原始 sequence、segment_sample_index 三者分别保存，不能互相冒充。
- 波形跨段断开；导出对缺口给出事件和原因，不插入伪造 ADC 点。

六、现有协议的关键接入规则

帧格式：[序号 1 字节][ADC 高字节][ADC 低字节]；ADC 合法范围 0～4095，0xFFFF 为导联无效。
协议没有帧头/CRC，不能宣称完整校验或绝对零丢样。

1. 打开串口后提示用户复位 STM32；沿用现有“0、1、2、3 连续序号”对齐规则。
2. 对齐前不把未确认数据送入波形/分析，可保存收到的字节供诊断。
3. 非法值触发锁定故障：停止本次采集，提示检查接线、重连和复位。
4. 序号异常、导联无效、ADC 饱和、接收超时都产生明确边界。
5. 必须检查 Sample.discontinuity；不能只用 Sample.step 推算是否连续。
   现有解析器遇重复序号时 step=1，但 discontinuity=True，忽略该标记会把异常两侧拼起来。
6. delta>1 的缺失计数仅作为模 256 推断量；delta=0 不能断言“丢失 255 点”。
7. 自动失步恢复和 CRC 升级属于后续固件与接收端联合修改，首版不假装已经支持。

七、滤波、参数和模型分支

显示/参数分支：
- 原始数据不改写。
- 显示可选原有 50 Hz 陷波；低阶因果带通建议从 0.5～40 Hz 的设计值验证。
- 滤波器保留跨块状态，分段后重置；验证频响、瞬态、分块一致性和相位影响。
- 首轮复用已有 RPeakDetector 接口，标为当前窗式检测方法。
- 课程要求的流式 Pan-Tompkins 另设实现和标注验证，不能仅给原检测器改名字。
- RR 和心率只来自同一有效连续段；信号失效后清空当前显示。
- SDNN/RMSSD 初期称 RR 统计预览；清洗、分析时长、有效率和剔除原因可追溯。
- 5 分钟 HRV、LF/HF 和参数越限提示在基本显示稳定后接入。

模型分支：
- 保留 seed42/43/44 三模型 softmax 概率平均，固定 N/PVC/PAC 顺序。
- 保留 360 Hz、180 点心拍（峰前 90 + 从峰起 90）、首尾去趋势、z-score、历史 RR。
- 保留原有模型前陷波与预热；10 秒核心窗口、左右各 2 秒上下文。
- 启用陷波后通常先需约 14 秒连续数据，再加加载和计算时间；不能描述为零延迟识别。
- 新增显示带通不能直接叠加到模型输入；两个分支独立维护状态。
- 队列溢出后递增 generation；后续首个成功入队块携带新代号，进程据此 reset。
  不依赖另外一条可能同样无法入队的 RESET 消息。
- 旧 generation 的迟到结果不得更新新段主屏；若保留历史结果，必须归回原段并标记迟到。
- 正常停止可 flush 尾段并标注 tail；故障断点不把前后数据拼接为尾段。
- 概率是未经校准的模型输出，不当作诊断置信度；现有模型不提供房颤类别。
- FP32/INT8 后续统一实现 Predictor 接口；INT8 未完成板端验证前仍标为待完成。

八、连续记录、SQLite 和导出

拟定树莓派路径：/home/pi2/ecg_terminal/；运行数据放 data/sessions/<session_id>/。
文件与表设计：
- session.json：来源、配置快照、实际设备、开始/结束、版本、最后成功提交位置和完成状态。
- chunks/：按约 1 秒提交的紧凑二进制采样块；分段时提前结束当前块。
- wire/：分块保留收到的原始串口字节，包含对齐前/非法字节，便于协议问题追溯。
- index.sqlite：sessions、chunks、events、metrics、beats、upload_queue 表。
- exports/：用户主动导出的完整 CSV、质量 JSON 和图表。

二进制格式需带 magic、schema_version、字节序和点数；不依赖 Python pickle。
数据字段至少含累计采样编号、段内索引、原始序号、ADC、质量标记；会话和段信息放块头/索引。
每个块计算 SHA256 用于存储/传输完整性；它不能补偿 UART 未检出的错误。

提交顺序：临时块写入 → flush/fsync → 原子改名 → SQLite 提交索引。
仅完成提交的块显示为“已保存”；界面分别显示收到点数、已保存点数和待写点数。
SQLite 单写者，事务和 WAL 参数由部署测试确认。启动时检查孤立块和未正常结束的会话。
断电恢复时只承认已验证块；尾部不完整文件标为恢复失败，不能伪装正常完成。
写盘失败或空间不足时停止本次接收，主屏保留明确错误；无法写入错误记录时至少保留屏幕/日志提示。
原始记录持续增长；30 秒显示缓存的淘汰不影响历史数据。
CSV 导出读取整个会话，包含 source_kind、session_id、segment_id、采样索引、序号、ADC 和质量。
优先在停止采集后进行大文件导出；不把最近显示缓存冒充完整 3 分钟数据。

九、控制状态机

IDLE → CONNECTING → WAITING_SYNC → RECORDING → STOPPING → IDLE
连接失败、协议失步、关键队列满、写盘失败 → FAULT → 人工处理后重新连接

- WAITING_SYNC：显示“串口已打开，请复位 STM32”；只有确认对齐后进入 RECORDING。
- 无数据超时显示“数据中断”，停止当前心率更新，并切断分析/模型上下文。
- 尚未对齐的等待和失步后的故障分别显示，不能混成正常采集中。
- paused_display 和 classifier_enabled 是独立开关，不改变原始保存是否持续。
- 正常停止：先结束接收，再排空已接收队列、提交数据、结束模型和线程。
- 窗口关闭也走同一停止流程；若无法及时结束，提示未完成状态，不能静默强杀后宣称保存成功。
- 自动重连、开机自动采集默认关闭；避免重连后误把旧串口缓冲数据当作新会话。
- 后续可开机启动界面，但界面就绪不等于硬件已经采集中。

十一、部署与本地屏幕运行设计

- 软件基础：系统 Python、NumPy、SciPy、pyserial、Tkinter/Tk、中文字体及轻量图形会话。
- ARM32 优先检查系统发行版提供的依赖；记录实际版本，再确定可复现安装清单。
- 先运行 Tk 示例验证本地屏幕，再验证波形 Canvas。远程 SSH 成功不能代替本地 GUI 验证。
- GUI 从树莓派本地图形会话启动；不把远程终端里的 DISPLAY=:0 当作通用授权办法。
- 提供显式 --headless 测试模式，在没有图形会话时仍能做协议/模型/录制验证。
- 提供 --demo、--replay 和真实串口三种模式，界面及文件必须携带来源标记。
- 串口优先选择稳定的 /dev/serial/by-id 路径；普通账号获得 dialout 权限后运行，应用本身不依赖 root。
- 初期手动启动；稳定后再配置当前图形会话的自动启动与日志轮转。
- 源码、配置和报告不保存 SSH 密码；部署凭据由开发环境管理。

十二、实现顺序和验收证据

A. 环境与屏幕骨架
   树莓派环境清单、Tk 窗口、中文字体、800×480 布局及全屏切换。
   合成波形演示明确标“模拟”，验证按钮和窗口退出，不冒充实采。

B. STM32 真实波形 + 完整保存（首版核心）
   接入 USB-TTL，验证对齐、实际接收速率、滚动显示及完整落盘。
   连续录制 3 分钟；360 Hz 的理论点数为 64800，实际以收到/保存的计数为准。
   验证暂停显示继续记录、停止后完整导出、拔线/导联无效/非法帧处理。

C. 心率与三分类接入
   分别验证参数路径和模型路径；用已有 36 拍参考核对数值，用连续流测吞吐。
   30 秒 stream_reference.npz 是合成、非 ADC 量纲参考，不能直接当作 AD8232 原始值输入。
   若转换为 ADC 模拟流，记录幅值/偏置转换规则，结果只归入模拟验证。
   记录每 10 秒核心任务的检测+推理用时、排队、结果延迟和未分类范围。
   是否全量在线跟得上必须依据 Pi 2 实测，不能依据电脑速度推断。

D. 故障、稳定性与报告
   做建议的 30 分钟稳定性测试，记录 CPU/内存/温度/降频和采集完整性。
   独立测试重复序号、序号跳变、解析失步、接收中断、队列满、写盘失败和模型崩溃。
   报告给出信号来源、有效率、观察到的序号异常、导联无效、平直/饱和和速率变化。

E. 后续课程功能
   加入 HRV、持续越限事件、历史检索；再接板外 HTTP 服务、断网补传、Web/App。
   同模型 INT8 的导出/校准/ARM32 引擎适配与板测另设任务；不能把 NumPy FP32 称为 INT8 完成。
   上传以 session_id + chunk_id 去重，只发送已提交数据；网络等待不阻塞本地屏幕或记录。
   云端地址和安装式 App 尚待具体交付条件，本文仅预留接口，不宣称已部署。

十三、设计审查结论与仍待板测项

本设计保持 STM32 为采样端、树莓派为本地显示和计算端；已有模型及固件无需因界面设计而改写。
已特别约束：重复序号分段、暂停显示仍保存、模型堵塞隔离、完整会话导出、来源标记和迟到结果处理。
尚待验证：实际屏幕/图形会话、串口接线与设备枚举、ARM32 依赖、三模型吞吐、界面帧率和存储稳定性。
