## 三、与 `run_checks.py` 的差异

| 点 | `run_checks.py` | 本工具 |
| --- | --- | --- |
| 云端/终端 | `unittest discover` | 相同 |
| 网页 | `node --test <多个文件>` | 逐个文件运行 `node <文件>`，避开受限环境禁止的进程派生 |
| 私有临时目录 | 依赖系统默认 | `--adapt-windows-sandbox` 在本进程内放宽 0700/0600 权限位，并向子进程注入同样的适配 |
| 输出 | 控制台 | 控制台表格 + `local-verification-v1` JSON |

三处适配**只作用于测试进程，不修改仓库任何文件，也不改变被测行为**；去掉适配后同样的用例会因权限错误大量失败，属环境差异而非代码缺陷。

## 七、复跑

```powershell
# 依赖：按 README「开发环境」安装，或把依赖放在独立的 PYTHONPATH 上
python tools/local_verification.py --suite all `
    --adapt-windows-sandbox --json "docs/中期检查/local-verification-20261125.json"
```

退出码：`0` 全部通过；`1` 存在真实失败或错误；`2` 仅有被环境阻塞的项（本机即属此类）。JSON 里 `totals.unexpected` 统计的是**排除环境阻塞后**的失败数，`totals.blocked` 列出被阻塞的套件。
